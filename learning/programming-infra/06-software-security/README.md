# 06. امنیت نرم‌افزار (مرز با امنیت سایبری)

نگارش: ۲۰۲۶-۱۰-۱۰ · پیش‌نیاز: — · بعدی: —

## چرا مهم است

بسیاری از آسیب‌پذیری‌های بزرگ از خطاهای کدنویسی و پیکربندی ناامن ناشی می‌شوند، نه از حملات پیچیدهٔ پنهان. امنیت نرم‌افزار یعنی ساختن امنیت در مرحلهٔ طراحی و کدنویسی. این حوزه از امنیت سایبری، که بیشتر به دفاع و پاسخ به حادثه می‌پردازد، متمایز است، هرچند با آن هم‌پوشانی دارد. هدف این گره رسیدن به عادت‌های امن در کد و وابستگی‌هاست.

## مفاهیم کلیدی

- **اعتبارسنجی ورودی** (input validation): بررسی و محدود کردن همهٔ داده‌های ورودی پیش از استفاده، برای جلوگیری از تزریق.
- **تزریق** (injection): ارسال ورودی مخرب که به‌عنوان دستور یا کوئری تفسیر می‌شود، مانند SQL injection.
- **احراز هویت و مجوزدهی** (authentication / authorization): تشخیص هویت کاربر در برابر تعیین اینکه چه کاری مجاز است؛ این دو یکی نیستند.
- **مدیریت وابستگی** (dependency management): پایش کتابخانه‌های شخص ثالث برای آسیب‌پذیری‌های شناخته‌شده، با ابزارهای تحلیل ترکیب نرم‌افزار (SCA).
- **مدل تهدید** (threat modeling): شناسایی دارایی‌ها، مهاجمان احتمالی و نقاط ورود، پیش از نوشتن کد.
- **اصل کمترین امتیاز** (least privilege): محدود کردن دسترسی برنامه‌ها و کاربران به حداقل لازم.
- **رمزنگاری و اسرار** (cryptography / secrets): استفاده از کتابخانه‌های استاندارد، پرهیز از ساخت الگوریتم رمزنگاری خانگی و نگهداری کلیدها خارج از کد.

## مثال

```python
# ناامن: ورودی کاربر مستقیم در کوئری قرار می‌گیرد
cur.execute(f"SELECT * FROM users WHERE name = '{name}'")

# امن: داده جدا از دستور ارسال می‌شود
cur.execute("SELECT * FROM users WHERE name = %s", (name,))
```

در نسخهٔ اول، مقدار ورودی می‌تواند بخشی از خود دستور SQL شود. در نسخهٔ دوم، پایگاه‌داده داده را هرگز دستور تفسیر نمی‌کند، پس همان ورودی مخرب فقط یک رشتهٔ معمولی است.

## اشتباه‌های رایج

- اعتماد به داده‌های سمت کلاینت، مانند قیمت یا نقش کاربر که در فرم یا کوکی آمده است. همیشه سمت سرور بررسی کنید.
- نصب کتابخانه بدون بررسی نگهداری و آسیب‌پذیری‌های آن، یا غفلت از به‌روزرسانی وابستگی‌ها.
- نمایش جزئیات داخلی خطا به کاربر. پیام خطا باید عمومی باشد و جزئیات در لاگ امن ثبت شود.

## بخش آموزشی و سنجش

### تمرین ۱۰ دقیقه‌ای

یک فرم ساده بسازید که نام کاربر را بگیرد و در پایگاه‌داده ذخیره کند. ابتدا بدون اعتبارسنجی و پارامتر بنویسید، سپس نسخهٔ امن را بسازید و دو کد را کنار هم مقایسه کنید.

### سؤال‌های سنجش

- **پلهٔ ۱** (explain): تزریق SQL را تعریف کنید و توضیح دهید چرا جدا کردن داده از دستور، این حمله را متوقف می‌کند.
- **پلهٔ ۲** (apply): برای یک API که هر کاربر فقط داده‌های خودش را ببیند، چه بررسی‌هایی لازم است؟ احراز هویت و مجوزدهی را در پاسخ جدا کنید.
- **پلهٔ ۳** (analyze/build): یک مدل تهدید ساده برای سرویس ثبت‌نام بنویسید که دارایی‌ها، سه تهدید احتمالی و کنترل متناظر هر تهدید را مشخص کند.

### معیار ارزیابی

- تعریف تزریق باید مسیر ورود داده ناامن به تفسیر دستور را دربرگیرد.
- پاسخ باید احراز هویت و مجوزدهی را جدا و با مثال توضیح دهد.
- مدل تهدید باید هر تهدید را به یک دارایی و یک کنترل مشخص وصل کند.
- پاسخ باید مرز میان امنیت نرم‌افزار و امنیت سایبری را روشن کند.
- کد امن باید از پارامتر یا ابزار معادل استفاده کند و فقط به ظاهر ورودی را پاک نکند.
