# ⭐ ۴. ایجنت‌ها و اتوماسیون

نگارش: ۲۰۲۶-۱۰-۱۰ · پیش‌نیاز: [۲](../02-prompting/README.md)، [۳](../03-tools-map/README.md) · بعدی: [۵. API و RAG](../05-api-rag/README.md)

## چرا مهم است
فرق «گفت‌وگو با AI» و «کارکردن AI برای شما» همین‌جاست. همین پروژهٔ نمایه نمونهٔ واقعی آن است: یک اجرای زمان‌بندی‌شده، ابزار Apify را صدا می‌زند، داده می‌گیرد، گزارش می‌سازد و push می‌کند — بدون حضور شما.

## مفاهیم کلیدی
- **استفاده از ابزار (tool use / function calling):** مدل به‌جای فقط متن، درخواست اجرای یک تابع را می‌دهد (مثلاً «جست‌وجو کن X»)؛ برنامه آن را اجرا و نتیجه را به مدل برمی‌گرداند.
- **جریان کار در برابر ایجنت:**
  - *جریان کار (workflow):* مسیر از پیش‌تعیین‌شده؛ مدل فقط در چند قدم استفاده می‌شود. قابل‌پیش‌بینی و ارزان.
  - *ایجنت:* مدل خودش تصمیم می‌گیرد قدم بعدی چیست و کدام ابزار را صدا بزند. انعطاف‌پذیر ولی گران‌تر و کم‌ثبات‌تر.
  - قاعدهٔ عملی: **اول ساده‌ترین جریان کار، بعد ایجنت فقط جایی که لازم است.**
- **ابزارهای بدون‌کد:** n8n (قابل میزبانی شخصی، متن‌باز)، Zapier و Make — گره‌ها را به هم وصل می‌کنید: «وقتی ایمیل آمد → خلاصه با LLM → ذخیره در شیت».
- **MCP (Model Context Protocol):** استاندارد باز برای وصل‌کردن مدل‌ها به ابزارها و منابع داده (فایل، پایگاه‌داده، سرویس‌ها) به‌صورت یکسان؛ «پریز برق» ابزارها برای ایجنت‌ها.
- **حافظه و وضعیت:** ایجنت برای کارهای طولانی باید وضعیت را جایی ذخیره کند (فایل، پایگاه‌داده) — مثل `pilot/log.md` در همین پروژه.
- **ایمنی و هزینه:** سقف هزینه، مجوزهای محدود، و توقف در موارد مشکوک؛ ایجنت نباید به هر ابزاری دسترسی آزاد داشته باشد.

## مثال
همین پروژه: `tools/monthly.py` یک *جریان کار* است (قدم‌ها ثابت‌اند)، و Routine ماهانه یک *ایجنت* را بالا می‌آورد که خطاها را مدیریت و گزارش را به زبان طبیعی می‌نویسد.

## اشتباه‌های رایج
- ساختن ایجنت پیچیده برای کاری که یک جریان کار سه‌مرحله‌ای کافی است.
- نبود سقف هزینه و ثبت رویداد (log).
- دادن دسترسی بیش از نیاز (مثلاً حذف فایل) به ایجنت.

## بخش آموزشی و سنجش

### تمرین ۱۰ دقیقه‌ای
یک کار تکراری خودتان را روی کاغذ به قدم‌ها بشکنید: ورودی → قدم‌ها → خروجی. کنار هر قدم بنویسید «ثابت» یا «نیاز به تصمیم». قدم‌های «نیاز به تصمیم» جای LLM هستند. نقشه را در `resources/` ذخیره کنید.

### سؤال‌های سنجش
- **پلهٔ ۱:** فرق جریان کار و ایجنت چیست؟ برای هر کدام یک مثال بزن.
- **پلهٔ ۲:** با n8n (یا ابزار مشابه) طرح یک اتوماسیون برای «هر روز ۵ پست جدید از منابع AI را خلاصه کن و برایم بفرست» بکش.
- **پلهٔ ۳:** ایجنتی که گاهی در حلقه گیر می‌کند یا هزینه‌اش بالا می‌رود را چطور عیب‌یابی و محدود می‌کنی؟

### معیار ارزیابی
- پاسخ باید جریان کار (مسیر ثابت) را از ایجنت (تصمیم‌گیری مدل دربارهٔ قدم بعدی) با معیار روشن جدا کند و برای هرکدام مثال بیاورد.
- طرح اتوماسیون باید ورودی، قدم‌ها، جای تصمیم LLM و خروجی را به‌ترتیب و قابل‌اجرا نشان دهد.
- پاسخ باید سازوکار محدودسازی، مثل سقف تکرار، سقف هزینه و ثبت رویداد (log)، را برای جلوگیری از حلقه و هزینهٔ بالا بیاورد.
- پاسخ باید دسترسی ایجنت را به حداقل نیاز محدود کند و این را به‌عنوان یک اصل ایمنی توضیح دهد.
